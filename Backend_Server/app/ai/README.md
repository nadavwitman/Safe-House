# app/ai

Backend integration layer between live sensor traffic / Firestore and the LSTM Autoencoder from [AI_Model/model_handler/](../../../AI_Model/model_handler/README.md). Handles per-request inference, per-house personalization (fine-tuning), and the nightly MLOps pipeline that keeps personalized models fresh. Actual scoring math (static-location / missing-usage / high-frequency, severity thresholds, hosting suppression) is not duplicated here — it lives in `model_handler.evaluate_window` and is only called into.

## Request flow

1. **[data_preprocessing.py](data_preprocessing.py)** `run_preprocessing_pipeline()` — turns raw ESP32 buffer readings into a scaled `[1, seq_len, 18]` tensor (expand sensor/location bit-vectors into columns, encode time as sin/cos, apply the cached `scaler.pkl`).
2. **[inference.py](inference.py)** `evaluate_buffer_with_AI()` — the main entrypoint called per sensor reading. Preprocesses the buffer, picks the personalized in-RAM model if one was passed in (else loads the global baseline checkpoint from disk), applies the house's sensor mask, and calls `model_handler.evaluate_window`. Returns `(sensor_id, decision_string, meta)`.
3. **[fine_tuning.py](fine_tuning.py)** `fine_tune_house_model()` — continual-learning retrain of one house's personalized model on its last ~14 days of data, called from the nightly pipeline (not from live inference).
4. **[model_manager.py](model_manager.py)** — orchestrates fine-tuning across all houses: which houses are due, fetching their data, persisting the retrained model to disk, and updating Firestore metadata.

**[model_paths.py](model_paths.py)** is the shared foundation all of the above import from: it resolves `AI_MODEL_DIR` (path differs between local dev and the Docker image — see its comment), adds it to `sys.path`, re-exports `model_handler`'s public symbols (`LSTMAnomalyDetector`, `evaluate_window`, etc.), and defines `masked_sensor_config()` (disables scoring for zones a house has no physical sensor for).

## Files

- **[model_paths.py](model_paths.py)** — resolves the `AI_Model/` directory path and checkpoint path (`MODEL_PATH`), imports and re-exports `model_handler`'s API, and `masked_sensor_config(house_sensor_mask)` — builds a per-house copy of `DEFAULT_SENSOR_CONFIG` with unmasked-off zones' `enabled` set emptied.
- **[data_preprocessing.py](data_preprocessing.py)** — `format_sensor_data()` (raw dicts → structured DataFrame with expanded sensor/location columns and cyclical time features) and `run_preprocessing_pipeline()` (format → select 18 feature columns in training order → scale via cached `scaler.pkl` → tensor). The scaler is loaded once and cached module-level since it's called once a minute per house.
- **[inference.py](inference.py)** — `evaluate_buffer_with_AI(buffer_data_list, latest_sensor_id, house_sensor_mask, model_instance=None, fine_tune_count=0)`: runs preprocessing, resolves which model to use (personalized `model_instance` from RAM cache vs. the global baseline loaded from `MODEL_PATH`), forces the decoder's `seq_len` to match the actual input (defends against legacy personalized models saved with a different window length), calls `evaluate_window`, and maps the result to a `"Emergency: <type>"` / `"Warning: <type>"` / `"Normal"` decision string plus a `meta` dict (`severity`, `activity_type`, `room_index`). Falls back to `("Normal", ...)` on any preprocessing or model-load failure so a bad reading never crashes the pipeline.
- **[fine_tuning.py](fine_tuning.py)** — `fine_tune_house_model()`: slices a house's recent data into overlapping 360-minute windows (`_build_training_windows`, same regime the base model was trained on, capped at 1000 windows), trains for a few epochs with the same asymmetric positive-sensor-weighted MSE used in the base [training notebooks](../../../AI_Model/training/README.md) combined with the house's installed-sensor mask, then blends the result 70% old / 30% new weights to avoid catastrophic forgetting. Returns the updated in-memory model, or `None` if there isn't enough data (`< 2 * WINDOW_SIZE` rows).
- **[model_manager.py](model_manager.py)** — the nightly MLOps orchestrator:
  - `HOUSES_MODELS_CACHE` — global in-RAM cache of loaded personalized models.
  - `download_model_from_firebase()` — despite the name, loads a pickled per-house model from local disk (`AI_Model/trained_models/<house_id>/anomaly_detector.pkl`) — Firebase Storage was skipped since it requires the paid Blaze plan.
  - `auto_train_house_model(house_id)` — per-house worker: fetches ~14 days of non-vacation data, loads the current model, calls `fine_tune_house_model`, persists the result to disk, updates Firestore (`last_retrained`, `fine_tune_count`, resets `vacation_days_total`), and refreshes `HOUSES_MODELS_CACHE`. Catches its own exceptions and records failures to Firestore so one bad house doesn't abort the run.
  - `run_weekly_mlops_pipeline_scalable()` — queries all active houses, filters to ones with 14+ *effective* days (calendar days minus accrued vacation days) since their last retrain or first-seen date, caps the batch to `MAX_HOUSES_PER_RUN` (currently 1, to bound Firestore reads), and dispatches them through a `ThreadPoolExecutor` (`MAX_CONCURRENT_WORKERS = 1`, since the single gunicorn worker shares CPU/GIL with live `/api/analyze` traffic).
